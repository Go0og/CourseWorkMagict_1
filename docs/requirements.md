# Технические требования

## Функциональные требования

### FR-1: Загрузка изображения
- Система принимает путь к PNG-файлу
- Поддерживаются разрешения от 640x480 до 3840x2160
- Изображение нормализуется до 1024x1024
- Путь к файлу в v0.1 жёстко задан в коде (константа IMAGE_PATH)

### FR-2: Детекция классов
- Система детектирует прямоугольники (классы) на изображении
- Для каждого класса определяется BBox (x_min, y_min, x_max, y_max)
- Точность детекции (mAP@0.5): > 0.85
- Поддержка множественных классов на одном изображении (минимум 1-50 классов)

### FR-3: Распознавание текста
- Система распознаёт текст внутри каждого класса
- Текст парсится на: имя класса, атрибуты, методы
- Атрибуты распознаются с типом и видимостью (+, -, #, ~)
- Методы распознаются с возвращаемым типом, параметрами и видимостью
- Точность распознавания (F1): > 0.80

### FR-4: Детекция связей
- Система детектирует линии между классами
- Определяется тип связи: association, inheritance, dependency, aggregation, composition
- Определяются кратности (multiplicity) на концах связей (1, *, 0..1 и т.д.)
- Точность классификации типов (F1): > 0.75

### FR-5: Экспорт в JSON
- Результат сериализуется в JSON по схеме (см. json-schema.md)
- JSON валидируется перед возвратом
- Формат: UTF-8, indent=2
- Выход содержит metadata (source_image, processing_time_ms, schema_version)

## Нефункциональные требования

### NFR-1: Производительность
- Inference time: < 2 секунды на изображение (GPU)
- Inference time: < 10 секунд на изображение (CPU)
- Memory footprint: < 2 GB (модель + данные)
- Поддержка batch processing (опционально в будущих версиях)

### NFR-2: Точность
- Полнота (Recall) детекции классов: > 0.80
- Точность (Precision) детекции классов: > 0.85
- F1 для атрибутов: > 0.80
- F1 для методов: > 0.80
- F1 для типов связей: > 0.75

### NFR-3: Воспроизводимость
- Результаты детерминированы (fixed random seed=42)
- Версионирование моделей (checkpoint hash в metadata)
- Логирование всех этапов обработки (INFO/DEBUG уровень)
- Возможность сохранения промежуточных артефактов (BBox, OCR results)

### NFR-4: Расширяемость
- Архитектура позволяет заменить YOLO на другую модель детекции
- Архитектура позволяет заменить PaddleOCR на другой OCR
- Конфигурация через YAML (без изменения кода)
- Каждый сервис независим и тестируем отдельно

### NFR-5: Качество кода
- Type hints везде (mypy --strict проходит без ошибок)
- Google style docstrings
- Покрытие тестами > 70%
- Ruff check без ошибок
- Функции не длиннее 50 строк
- Классы не длиннее 200 строк

## Тестовые сценарии

### TC-1: Простая диаграмма (3 класса, 2 связи)
**Вход**: PNG с 3 классами (User, Order, Product), 2 связями (association)
**Ожидаемый выход**: JSON с 3 UmlClass, 2 Relation
**Проверка**: 
- Все имена классов распознаны корректно
- Все атрибуты и методы извлечены
- Типы связей определены верно
- BBox координаты валидны (x_min < x_max, y_min < y_max)

### TC-2: Диаграмма с наследованием
**Вход**: PNG с классом-родителем (Animal) и 2 дочерними (Dog, Cat)
**Ожидаемый выход**: 2 Relation типа "inheritance"
**Проверка**: 
- Правильная направленность связей (от дочернего к родителю)
- Тип связи inheritance распознан
- Стрелка/треугольник детектирован

### TC-3: Диаграмма с атрибутами разных видимостей
**Вход**: PNG с атрибутами + (public), - (private), # (protected), ~ (package)
**Ожидаемый выход**: Корректные visibility в JSON
**Проверка**: 
- Все 4 типа видимости распознаны
- Символы +, -, #, ~ корректно маппятся на enum

### TC-4: Диаграмма с методами и параметрами
**Вход**: PNG с методами, имеющими параметры (login(password: String): bool)
**Ожидаемый выход**: Корректные parameters в JSON
**Проверка**: 
- Имена параметров распознаны
- Типы параметров распознаны
- Возвращаемый тип метода распознан

### TC-5: Диаграмма с кратностями
**Вход**: PNG со связями 1:*, 1:1, 0..1:*
**Ожидаемый выход**: Корректные multiplicity в JSON
**Проверка**: 
- Все кратности распознаны
- multiplicity_source и multiplicity_target заполнены

### TC-6: Пустая/невалидная диаграмма
**Вход**: PNG без классов или не UML-диаграмма
**Ожидаемый выход**: JSON с пустым списком classes
**Проверка**: 
- Система не падает с ошибкой
- Возвращается валидный JSON с metadata
- processing_time_ms > 0

### TC-7: Большая диаграмма (20+ классов)
**Вход**: PNG с 20-50 классами
**Ожидаемый выход**: JSON со всеми классами
**Проверка**: 
- Inference time < 10 сек (CPU)
- Memory footprint < 2 GB
- Все классы детектированы

## Метрики качества

### Технические метрики
```python
{
    "mAP_0.5": 0.85,          # Mean Average Precision @ IoU=0.5
    "precision_classes": 0.88, # Precision для детекции классов
    "recall_classes": 0.82,    # Recall для детекции классов
    "f1_attributes": 0.83,     # F1-score для атрибутов
    "f1_methods": 0.81,        # F1-score для методов
    "f1_relations": 0.76,      # F1-score для типов связей
    "inference_time_ms": 1850, # Среднее время обработки
    "memory_mb": 1450          # Пиковое потребление памяти
}
```

### Бизнес-метрики (для диссертации)
- Полнота извлечения (Completeness): % распознанных элементов от общего числа
- Точность извлечения (Correctness): % корректно распознанных элементов
- Соответствие ТЗ: % элементов, соответствующих текстовому ТЗ
- Время обработки: среднее время на одну диаграмму
- Удовлетворённость экспертов: оценка качества экспертами (1-10)
